What this tool does - and does not do

The dashboard performs passive open-source intelligence: it reads information that is already public (DNS, registration data, certificate-transparency logs, public profile pages) or available through authorised APIs (Have I Been Pwned, VirusTotal). It never port-scans, probes for vulnerabilities, attempts logins, or bypasses CAPTCHAs, access controls or platform restrictions.

The one exception is the TLS check: like any web browser, it opens a single HTTPS handshake on port 443 to read the certificate the site presents, then closes the connection. Hosts that resolve to private or internal addresses are never contacted.

How the relationship graph works

Every confirmed item becomes a node (domain, IP address, server, subdomain, certificate authority, third-party service, account, breach, data type or risk issue) and every relationship becomes a labelled edge. Nodes have a canonical identity, so when two scans discover the same entity they share one node. The investigation graph merges stored scans this way, which is how separate findings are correlated.

How results are labelled

Confirmed
The source positively reported this observation.
Inconclusive
We could not tell: blocked, rate-limited, redacted or ambiguous. Never counted as found.
Not found
The source answered and reported nothing.
Error
The source could not be reached or returned an invalid response.

Exposure score

The score is the sum of severity weights of confirmed findings, capped at 100: high 20, medium 10, low 4, informational 0. Inconclusive, not-found and failed lookups add nothing. Levels: 0-19 Low, 20-49 Moderate, 50-74 High, 75-100 Critical. Every scan shows exactly which findings produced its score.

Safeguards built into the application

  • Live lookups require ticking an authorisation statement for that specific target; the server rejects live requests without it and stores the statement with the scan.
  • Demo mode uses only fictional targets on the reserved .test domain, so the application can be presented without querying anyone real.
  • Email checks: the address is sent only to Have I Been Pwned; it is stored, logged and reported in masked form. Optional AUTHORIZED_EMAIL_DOMAINS restricts live checks to your organisation.
  • API keys live in the .env file, never in source code or reports.
  • Rate limiting on every scan endpoint, per-source timeouts, and a local guard for the VirusTotal free-tier quota.
  • Strict input validation; private and internal IP addresses are rejected.
  • Content-Security-Policy and other security headers; third-party data is always rendered as text, never as HTML. CSV exports are protected against formula injection.
  • Stored scans are deleted after the retention period and can be deleted at any time.

Data sources

  • RDAP via the IANA bootstrap registry, with WHOIS (port 43) fallback for TLDs without RDAP.
  • DNS via the operating system's resolver (dnspython).
  • crt.sh certificate-transparency search.
  • TLS certificate of the domain, read with Python's standard ssl module.
  • Public profile pages and public APIs of the platforms in collectors/sites.json (detection approach adapted from the open-source Sherlock project).
  • Have I Been Pwned API v3 (paid key, or the official test key for test addresses).
  • VirusTotal API v3, free community tier.
